# Boreas 設計書(案)

2026-11-23 時点の案です。

## 1. 目的と位置づけ

Notos から、画像を作る機能を別のアプリに分けて独立させます。

| アプリ | 役割 |
|---|---|
| **Notos** | 小説を書く。キャラクターシートと表紙・挿絵は **取り込むだけ** にする |
| **Euros** | キャラクターシートを作る(人物と、人ではない登場人物) |
| **Boreas** | 表紙・挿絵・背景を作る |

受け渡しは次のとおりです。

```
Euros ──シート──▶ Notos                  (キャラクターシート)
Euros ──シート──▶ Boreas ──画像──▶ Notos  (表紙・挿絵)
Notos ──本文・場面・場所──▶ Boreas        (場面の案の材料。読むだけ)
```

**ルール**:データはそれを作ったアプリだけが書き、ほかのアプリは読むだけにします(今の Euros と同じ)。このため、Notos と Euros にも変更が必要です(10章)。

### Boreas の考え方

- 人物・人ではない登場人物・部屋・家具を、**実際の大きさを持った 3D の目安** として置く。
- 構図、距離感、大きさの関係、カメラから見えるものを 3D で決め、下絵を作る。
- 見た目(デザイン)はシート(画像)で決める。下絵とシートを MiniMax-H3-Image に渡して清書する。
- 3D は **位置と大きさとポーズを伝えるためだけ** に使う。3D 自体を作り込むことはしない。

日本語の説明だけでは、距離感や大きさ(例:鈴がバットをスライムに振り下ろす)が崩れました。それを、3D の目安で解決するのが狙いです。

## 2. 検証で分かったこと

| 検証 | 結果 |
|---|---|
| 棒と球の人形1体 + シート → 清書 | ポーズ・顔・服・小物がシートどおりに描けた |
| 色分けした人形2体 + シート2枚 → 清書 | 赤 = 1人目、青 = 2人目の対応が崩れず、髪・顔・服が混ざらなかった。seed を変えても構図は安定 |
| MakeHuman の素体2体 → 清書 | 棒の人形より、体の向き・視線・手の形がはっきり良くなった |
| 残った弱点 | 人物と小物が触れる表現(バットの先が胸に当たる、など)は弱い。表情の指示は通りにくい |

- 1枚(1632×2592、約4MP)の清書に約6分かかる(このPCのGPU)。
- 範囲の描き直しは背景まで描き変わるので、挿絵の修正には使わない。

## 4. 全体の流れ

```
Euros(読むだけ)                 Notos(読むだけ)
  人物・人ではない登場人物のシート     本文・場面・共通の場所
          │                              │
          └──────────┬──────────────────┘
                     ▼
  Boreas
   ① 場所を用意する:間取り図に家具を置く(実際の寸法)、
      部屋・家具のデザインを日本語の説明から作る
   ② 場面を作る:人物・人ではない登場人物を場所に置く → ポーズ → カメラ
      (AI(Ollama)が本文から配置とポーズの案を出す)
                     ▼
   ③ 下絵を撮る:人物・物ごとに色分けした 3D の画像
                     ▼
   ④ 清書する(ComfyUI の MiniMax-H3-Image)
      Picture 1 = 下絵、Picture 2〜 = 人物のシート・部屋や家具のデザイン
                     ▼
   ⑤ 候補から1枚を選び、Boreas のライブラリに保存
                     ▼
  Notos が取り込む(表紙・挿絵の候補として)
```

## 5. 機能

### 5.1 キャラクター

- Euros のライブラリ(Euros の `docs/character-format.md` で決まっている場所)から一覧を読む。読むだけにする。
- 使う項目:`profile.name`、`appearance.*.en`、`style`、`sheet.notHuman`、採用中の版のシート画像。
- 人物の場合、身長・体型(`appearance.height` / `body`)から素体の種類と身長の初期値を決める。日本語の説明から数値を取り出すのは Ollama に任せ、画面で直せるようにする。
- 人ではない登場人物の場合、形の種類と大きさ(5.3)を Euros の新しい項目から読む。項目がないときは Ollama が説明から推定し、画面で直せるようにする。

**M3 で読んでいる形(Euros の `character-format.md` が決まるまでの仮の形)**

| 項目 | 形 | 読めないとき |
|---|---|---|
| `sheet.notHuman` | `true` なら人ではない登場人物として置く | 人物として置く |
| `body.form` | `"sphere"`・`"blob"`・`"quadruped"`・`"biped"`・`"object"`(別名 `ball`・`slime`・`amorphous`・`monster`・`box`、`球`・`不定形`・`四足`・`二足`・`物` も読む) | 説明の文章から推定する(スライム → 不定形 など) |
| `body.size` | m。`sphere`:`diameter`、`blob`・`object`:`width`・`depth`・`height`、`quadruped`:`length`(体長)・`height`(体高)、`biped`:`height`・`width`(肩幅)。`heightCm` のように `Cm` で終わる項目は cm として読む | 足りない項目は形の種類の初期値 |
| `body.arms`・`body.tail` | 腕・尾があるか(なければ「ある」) | ある |
| `heightCm` | 人物の身長(cm) | `appearance.height` の文章から読む |

### 5.2 人物の素体

- MakeHuman の素体を前もって作り、`public/figures/*.glb` として同梱する。利用者の PC に Blender は要らない。
- 最初に用意する種類(案):女性・男性 × 細身・標準・がっしり の6種類。身長はアプリで拡大・縮小する。
- 骨格は指まである `game_engine`(53本)。
- 頭身の調整(アニメ寄りに頭を大きくする)は、頭の骨の拡大で行う。自前の素体なので問題ない。
- 素体を作るスクリプト `tools/make_figure.py` もリポジトリに入れる(MPFB2 で作り、glTF に書き出す)。
  - **注意**:`create_human` で関節用の補助頂点(`detailed_helpers`)を外すと、骨格が体からずれる。外さないこと。

### 5.3 人ではない登場人物

人物と同じく、3D は「形・大きさ・向き・ポーズ」の目安です。見た目は Euros のシート(`notHuman`)で決めます。

**形の種類**(素体の型):

| 型 | 3D の目安 | 動かせるところ | 例 |
|---|---|---|---|
| 球 | 球(直径を指定)。正面の印(目・レンズの位置)付き | 浮く高さ、向き、傾き | まるるん(自立型AI搭載ドローン、丸い玉) |
| 不定形 | 柔らかい塊(幅・奥行き・高さを指定)。つぶれ・伸び・へこみを付けられる | 形の崩れ具合、へこみの位置(叩かれた所など) | スライム(巨大なわらび餅) |
| 四足 | 骨格つきの四足の素体(体長・体高を指定) | 首・脚・尾 | 犬、猫、狼型の魔物 |
| 二足の怪物 | 骨格つきの大型の素体(身長・体の太さ・腕や尾の有無) | 腕・脚・首・尾・口 | 階層主(怪獣型の魔物) |
| 物 | 箱・円柱などの組み合わせ | 置き方だけ | ロボットのような機械、動かない物 |

- M3 では、どの型も素体のファイルを持たず、型と大きさから three.js で簡単な形を作る(`src/lib/creatures.ts`)。四足・二足の怪物は、円柱と球を関節(首・脚・尾・腕・口)でつないだ骨組み。
- 色は人物と同じ並び(赤・青・緑・橙)から、人物と重ならない色を付ける。場面に置ける数は、人物と合わせて4まで(参照画像の数)。
- 不定形のへこみは、部位(上・正面・横・背中)と深さで決める。触れる点がへこんだ部位を指すと、先はへこみの底に届く。

- 大きさはメートルで持つ。人物と並べたとき、大きさが自然に正しくなる。
- 四足と二足の怪物の素体は、自前で作る(Blender のスクリプトで、骨格つきの簡単な形を作る)か、CC0 の素材を使う。
- 当たり判定:武器が体に当たる、めり込む、を目で確かめられるようにする(5.5 の「触れる」と同じ仕組み)。
- 確かめたい場面の例:**天音鈴が振りかぶったバットを、スライムに振り下ろす**。鈴の身長 150cm に対して、スライムの大きさ、距離、バットの軌道を 3D で決める。

### 5.4 場所(部屋・家具)

同じ部屋の別の場面(机に向かっている時、ベッドに腰かけている時)で、カメラの位置によって見える物が食い違わないようにします。そのために、部屋を **間取り図と寸法** で持ちます。

| 項目 | 内容 |
|---|---|
| 間取り | 床の形(長方形の組み合わせ)、天井の高さ、壁、窓・ドア(位置と大きさ)。上から見た間取り図の画面で描く |
| 家具 | ベッド・机・椅子・本棚・タンス・テレビなどの型。幅・奥行き・高さ(cm)を持つ。間取り図の上でドラッグして置き、回す |
| 寸法の点検 | 部屋に入らない、壁や他の家具にめり込む、ドアや窓をふさぐ、を警告する。家具の型ごとに、ありえない寸法(高さ3mの椅子など)も警告する |
| 人物との関係 | 座る(椅子・ベッドの座面の高さに合わせる)、寄りかかる、机に手をつく、を素体に当てはめる |
| デザイン | 部屋と家具ごとに、日本語の説明(「木目の勉強机、上に古いモニター」など)から、ComfyUI でデザインの画像を作る。キャラクターシートの家具版。デザインを直すと、その場所のすべての場面に効く |
| 3D の見た目 | 箱を組み合わせた目安(ベッド = 台 + マットレス + 枕、机 = 天板 + 脚)。家具ごとに色を変え、下絵で区別できるようにする |

**清書での使い方**

- 下絵には、人物と家具を色分けして写す。
- プロンプトで、色と家具の対応(「茶色の箱 = Picture n の机」)と部屋の説明を伝える。
- 参照画像の数が増えすぎる場合は、主な家具だけデザイン画像を渡し、ほかは文章で伝える。何枚まで渡せるかは要検証。
- 部屋だけの絵(人物なし)を先に作り、それを背景の参照にする方法も検証する。

**M4 で作ったもの**

- `place.json`:`floor`(長方形 `{ x, z, width, depth }` の組み合わせ、cm)・`ceilingCm`・`openings`(窓・ドア:壁の上の中心 `x`・`z`、`widthCm`・`heightCm`・`sillCm`)・`furniture`(`kind`・`name { ja, en }`・中心 `x`・`z`・`rotation`・`widthCm`・`depthCm`・`heightCm`・`seatCm`・`elevationCm`・`color`・`design`)・`description`・`design`。座標は場面と同じ(cm と m の違いだけ)で、場面の人物は部屋の座標に立つ。
- 家具の型:ベッド・机・椅子・ソファ・テーブル・本棚・タンス・低い棚(テレビ台)・テレビ・箱。型ごとに寸法の初期値と、ありえる寸法の範囲を持つ。
- 寸法の点検:机・テーブルは天板の高さだけ、椅子は座面までをぶつかる範囲にする(机の下の椅子、台の上のテレビを警告しない)。ドアは前の 60cm、窓は前の 20cm(窓の高さにかかる家具だけ)をふさぐと警告する。
- 3D:壁と天井は内側からだけ見える面にする(部屋の外にカメラを置くと手前の壁が写らない。画面でも知らせる)。
- カメラから見える家具:家具の箱の中の点(27点)を写し、画面の中にあって壁・他の家具に隠れていない点の割合で決める。点で拾えない、画面の端に少しだけ写る家具は、家具ごとに色を変えて小さく描いた画像の画素で拾い、「一部」としてプロンプトに書く(書かないと、清書で別の物(ドアなど)に描かれた)。見えない家具はプロンプトに書かず、デザインも渡さない。渡す画像は下絵を含めて最大8枚(人物 → 装備品 → 部屋 → 見えている割合の大きい家具)。
- デザイン:説明(英語)から MiniMax-H3-Image で描く(参照画像なし)。部屋は 1600×1120、家具は 1024×1024。作り直しても前の画像は消さず、清書の記録(`Take.sheets`)に使った画像を残す。
- 誇張(5.5.1)は家具にはまだない。Notos の「共通の場所」との結び付けと、Ollama による間取りの案は M5。

**場所の持ち主**

- 場所(部屋・家具)と、そのデザインは Boreas のライブラリに保存する。
- Notos の「共通の場所」と名前で結び付け、Notos の説明を最初の案に使う(読むだけ)。

### 5.5 場面の編集

| 項目 | 内容 |
|---|---|
| 場所 | 5.4 の場所を選ぶか、場所なし(背景は文章だけ)にする |
| 人物 | Euros のキャラクターを選んで置く。人物ごとに色が自動で付く。最大4人(参照画像の数と、描き分けの安定性から。要検証) |
| 配置 | 間取り図か 3D の床の上でドラッグして、位置と向きを決める |
| ポーズ | ①ポーズの一覧(立つ・歩く・走る・座る・振りかぶる・振り下ろす・指差す…)から選ぶ。②関節をつかんで、腕や脚を伸ばす向きを決める(検証で使った「骨を指定した向きに向ける」仕組み)。③首・胴のひねり |
| 手 | 開く・握る・指差す・ピース などの形から選ぶ |
| 視線 | 「この人物・物を見る」「カメラを見る」を選ぶと、首と頭を向ける |
| 小物 | 5.5.1 のとおり。寸法を持ち、手に持たせられる |
| 触れる | 「Aの手 → Bの肩」「バットの先 → スライムの頭」のように、触れる点を指定すると寄せる(手は IK で届かせ、小物は先を相手に向ける)。プロンプトでも伝える。触れる点の印は編集の画面にだけ出し、下絵には写さない(M2 の検証で、下絵の黒い印が清書に描かれることがあり、触れる表現にも効かなかったため) |
| カメラ | 画角・高さ・向き。枠は表紙(1600×2560)、挿絵(縦・横)、自由。場所があるときは、そのカメラから見える家具の一覧を出す |

#### 5.5.1 小物・装備品と大きさの誇張

- 小物と装備品(バット・剣・鞄など)は、人物と同じく **実際の寸法** を持つ。
  - Euros で登録した装備品は、Euros から読む(Euros で作成中の装備品の登録機能)。寸法とデザインの画像も Euros で持つ。
  - Euros にない一時的な小物は、Boreas で型(棒・箱・円柱など)と寸法を指定して置く。
- 3D の形の目安は、型と寸法から作る(バット = 先が太い円柱、剣 = 刃 + 柄 など)。下絵では人物と違う色にし、プロンプトで「この色の物 = Picture n の装備品」と伝える。
- **誇張**:場面ごとに、物の大きさを実際の寸法から変えられるようにする。
  - 例:見せ場で、バットを実際より大きく(×1.5)描く。スライムを実際より巨大に見せる。
  - 誇張は場面だけに効く。装備品や登場人物の寸法(Euros の値)は変えない。
  - 倍率を全体・長さ・太さで指定できるようにする。下絵の 3D もその大きさで描くので、手に持つ位置や当たる位置も誇張後の大きさに合う。
  - 「誇張しているか」は scene.json に残し、画面でも分かるようにする(寸法の点検で、誇張した物を警告しない)。
- 人ではない登場人物(5.3)と家具(5.4)にも、同じ誇張を使えるようにする。人ではない登場人物の「長さ」は縦(高さ・体長・直径)、「太さ」は横(幅・奥行き)の倍率。

**M3 で読んでいる装備品の形(Euros の文書が決まるまでの仮の形)**

- 場所:Euros のライブラリの `equipment/<id>/equipment.json`(`app: "Euros"`)。画像は `designs/`・`sheets/`・`images/`・`refs/` の中だけを読む。
- `name`(文字列か `{ ja, en }`)、`description`(`{ ja, en }`)、`shape`(3D の目安の型:`bat`・`blade`/`sword`・`rod`/`stick`・`cylinder`・`ball`・`box`。日本語の `バット`・`刃物`・`棒`・`円柱`・`球`・`箱` も読む)、`size`(cm:`lengthCm`・`widthCm`・`thicknessCm`・`heightCm`・`diameterCm`)、`revisions[].image` と `currentRevision`、または `image`(デザインの画像)。
- 型がなければ名前と説明(「金属バット」→ バット)から、それでも決まらなければ寸法の比(長さが太さの 2.5 倍より長ければ棒、そうでなければ箱)で決める。寸法がなければ型の初期値(バットは長さ 84cm)。
- 2026-11-27 時点の Euros の装備品は `name`(文字列)・`description`・`category`・`image`(`refs/…`)だけで、型と寸法はまだない(10章)。
- 場面には `equipment: { id, revisionId }` を残し、寸法は Euros の値のまま変えない(画面でも直せない)。デザインの画像は、登場人物のシートの次の Picture として渡す。

### 5.6 AI による自動化(Ollama)

- Notos の場面の本文(または作者が書いた一言)から、場面の案を JSON で作る。内容は、場所、登場人物、立ち位置、ポーズ(一覧の名前 + 関節の向き)、視線、小物、触れる点、カメラ、表情。
- 部屋と家具の日本語の説明から、間取りと家具の寸法の案を作る。
- 人ではない登場人物の説明から、形の種類と大きさの案を作る。
- 案を 3D に当てはめて表示し、作者が直す。
- 清書のプロンプトの英文も作る(日本語で見せて、直すと訳し直す。Notos と同じ流れ)。

### 5.7 清書

- エンジンは MiniMax-H3-Image(Euros の `engines.ts` と同じ設定:6ステップ、CFG 1、約4MPで描く)。
- 渡す画像:Picture 1 = 下絵、Picture 2〜 = 人物・人ではない登場人物のシート(色の順)、部屋・家具のデザイン。
- プロンプトの骨組み(検証で効いた形):
  - 「Picture 1 は 3D の下絵。位置・ポーズ・体と頭の向き・手足・小物・大きさの関係・カメラ・構図だけを使う。素体や裸の体、素体と箱の色は描かない」
  - 「赤の素体 = Picture 2 の人物(外見の英文)。動作と表情」…を人数分
  - 「茶色の箱 = Picture n の机」…を家具の数だけ
  - 「それぞれのシートどおりに描き、髪・顔・服を混ぜない」「画風はシートに合わせる」「部屋・背景の説明」
- 候補を数枚作る(seed 違い)。生成の前に Ollama のモデルを GPU から外す(Notos と同じ)。
- 下絵・プロンプト・seed・使ったファイルをすべて残し、同じ絵を作り直せるようにする(Euros の Revision と同じ考え)。

### 5.8 Notos への受け渡し

- できた絵は Boreas のライブラリに保存し、形を `docs/image-format.md` に書く(Euros の `character-format.md` と同じ書き方)。
- Notos は「Boreas から取り込む」で、表紙・挿絵などの候補画像として読み込む。

## 6. 画面

1. **場面の一覧**:作品・話ごとに並べる。新規作成は「Notos の場面から」と「白紙から」。
2. **場所**:間取り図の編集(上から見た図)と 3D 表示。家具の一覧と寸法、デザインの画像。
3. **場面の編集**:中央に 3D 表示。左に人物・物の一覧、右に選んだもののポーズ・手・視線。上にカメラと枠。
4. **清書**:下絵とプロンプト(日本語と英語を左右に並べる)、候補の一覧、採用。
5. **設定**:ComfyUI・Ollama の接続、Euros のライブラリ、Notos のデータの場所。

## 7. 保存

```
%APPDATA%\Boreas\library\
  places\<id>\
    place.json         … 間取り・家具(型・寸法・位置・向き)・説明
    designs\<id>.png   … 部屋・家具のデザイン
  scenes\<id>\
    scene.json         … 場所・人物・素体・ポーズ(骨ごとの回転)・小物・触れる点・カメラ・プロンプト
    sketches\<版>.png  … 下絵
    results\<版>.png   … 清書の候補
```

`scene.json` には、元にした Notos の作品・話・場面と、Euros のキャラクター id・版 id を残す。

## 8. 技術構成

- Tauri 2 + React 19 + TypeScript + Vite(Euros・Notos と同じ)
- 3D は three.js(GLTFLoader、骨のポーズ、下絵は WebGL の画面をそのまま PNG にする)
- 間取り図は 2D の画面(SVG か Canvas)で、3D と同じデータを編集する
- ComfyUI・Ollama の呼び出しは Euros の実装を流用する
- 識別子 `io.github.kurone-hinamori.boreas`、実行ファイル `Boreas`

## 9. リリース

Euros と同じ形にする。

- `.github/workflows/ci.yml`(プルリクエストの検証)、`release.yml`(`v*` タグでビルドし Releases に公開、`latest.json` 付き)、`bump.yml`(Actions から実行してバージョンを上げ、そのままリリース)
- `scripts/bump.mjs` で package.json・Cargo.toml・tauri.conf.json・Cargo.lock をそろえる
- 更新の署名鍵は `~/.tauri/boreas.key`。Secrets に `TAURI_SIGNING_PRIVATE_KEY` と `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` を登録する

## 10. Notos・Euros に必要な変更

| アプリ | 変更 |

## 11. 進め方

| 段階 | 内容 | できたら確かめること |

| M2 | 複数人と色分け、関節をつかむポーズ、手の形、視線、小物、触れる点 | 2〜3人の挿絵が作れる(**済**:2026-11-26、鈴とカイの2人で確認。3人は未確認) |
| M3 | 人ではない登場人物(球・不定形から。次に四足・二足の怪物)、Euros の装備品の読み込み、大きさの誇張 | 鈴がバットをスライムに振り下ろす場面が、距離感と大きさのとおりに描ける(**済**:2026-11-27、鈴(150cm)・幅160cm のスライム・Euros の金属バットで確認。スライムのシートは検証用に作ったもの) |

## 12. 未検証のこと

- 3人以上の場面
- 座る・寝転ぶ・抱き合うなど、体が重なるポーズ
- 手のアップ、極端な煽り・俯瞰
- 触れる点:M2 の検証(バットの先をカイの胸に当てる)では、2枚とも先が胸の手前で止まった。下絵の黒い印は効かず、1枚では印そのものが描かれた。印をやめ、文章で「すき間なく触れる」と伝える形にしたところ、次の1枚では先が胸に届いた(1枚だけなので、引き続き確かめる)
- 人ではない登場人物:M3 の検証(鈴がバットをスライムに振り下ろす)では、不定形の目安からシートどおりのスライムが描け、身長 150cm の鈴との大きさ・距離・バットの先がへこみに入る位置も下絵どおりだった(2枚)。ただし、触れる点に腕を伸ばすので振り下ろすより「押し込む」姿勢に見え、1枚では左手がバットから離れ、床の円も描かれた。球・四足・二足は未確認
- 誇張:実際より大きくしたバットなどを、清書がその大きさのまま描くか(シートの寸法に引き戻されないか)
- 部屋:家具を色分けした下絵 + デザイン画像で、配置どおりの部屋が描けるか。渡せる参照画像の枚数。M4 の検証(鈴の部屋、机に向かう場面、参照画像6枚)では、机・椅子・窓・タンスが下絵どおりの位置と向きで、デザインどおりに描けた。ただし床が下絵の灰色のまま描かれ(プロンプトで「部屋の素材と色で描く」と足した。未確認)、画面の端に少しだけ写ったベッドがドアに描かれた。参照画像6枚の清書は1枚約15分かかり、2枚目の途中で ComfyUI が止まった
- 表情:シートの表情一覧から顔を切り抜いて追加で渡す方法
- 裸の素体が服装に影響しないか(今回は問題なし。気になれば素体に簡単な服の形を付ける)

M3・M4 に入る前に、今回と同じやり方で、まず清書だけの検証をする。

## 13. 決めること

1. 素体の種類:人物6種類で足りるか。子ども・年配をどうするか。
2. 人ではない登場人物の形と大きさを、Euros で持つか、Boreas で持つか(案:Euros で持つ。シートと同じ所にあると、Notos からも使える)。
3. 場所(部屋・家具)を Boreas で持つか、Euros のように別のアプリにするか(案:Boreas で持つ)。
4. M1 に Euros の読み込みを入れるか。入れない場合、シートの画像ファイルを直接選ぶ。
